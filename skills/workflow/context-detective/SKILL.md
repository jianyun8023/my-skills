# Context Detective — 上下文侦探

取得足以支持当前决策的仓库证据，然后继续完成用户任务。调查深度由未知信息对决策的影响决定；多文件、新文件或敏感模块本身不要求全量调查。

## 范围与自主性

- 用户明确指令优先于本技能的流程建议；遵守适用的系统、开发者指令及实际权限边界。不要把建议检查解释成额外审批条件。
- 从当前请求及已确认上下文确定目标、约束和完成标准。精确且低风险的局部修改直接处理；已有证据仍有效时复用，仅在范围、代码或关键假设变化后补查受影响部分。
- 实现请求在证据足够后继续修改和验证；只读、计划或审查请求按用户边界交付。不要在探索结束时额外询问是否开始已授权的工作。

## 按决策需要取证

以下是可选择的调查路径，不是每次必须走完的阶段。

- **定位：** 从给定文件、符号、错误、测试、日志或 diff 出发。修改前检查相关工作区改动和适用的目录规则，避免覆盖已有工作。
- **检索：** 优先用路径、符号和错误文本搜索；术语不明时再用可用的语义检索。打开命中的源码或配置确认上下文，搜索摘要只作为线索。
- **追踪：** 当行为依赖调用关系时，沿相关入口、实现和下游契约追踪到足以判断影响的位置。静态配置或局部转换可直接检查使用点，无需凑齐整条调用链。
- **扩展：** 仅在当前证据留下会改变方案的缺口时扩大范围。独立读取可批量并行；后续检索应依据实际结果调整。

针对具体决策选择证据：

| 决策 | 通常需要的证据 |
| --- | --- |
| 修复局部行为 | 目标实现、相关调用者，以及测试或最小复现中足以解释问题的部分 |
| 新增文件或组件 | 预期目录和相关模块内的同职责实现、命名及集成惯例 |
| 引入或推荐依赖 | 现有依赖声明、相关锁定版本和用法，判断现有能力是否足够 |
| 改动数据、公共 API、认证或权限契约 | 与变更有关的模型、注册点、执行链、调用方；涉及迁移、兼容性或失败路径时继续追踪 |

搜索未命中只能说明在已查范围内未找到。结合目录与引用判断是否值得扩大检索，不以“证明全仓库不存在”为完成条件。缺少惯例或测试不自动阻止工作：采用与已读实现相容的最小方案，并说明影响结论的缺口。

## 证据与未知信息

- 区分已读取事实、基于证据的推断和仍未知事项；需要复核时附路径与符号。不要把代码阅读当作运行验证，也不要把框架惯例当作项目事实。
- 源码、测试、文档不一致时，针对冲突检查实际入口、版本或最小复现；保留尚未解释的差异，不反复搜索直到得到期望答案。
- 查 API 或框架文档时使用 Context7，并核对项目使用的版本。不可用或覆盖不足时使用官方来源并说明缺口；仓库事实仍以当前实际实现为准。按需查文档，不为每次探索强制联网。
- 能从仓库解决的未知先自行取证。对可逆、局部且有合理默认值的选择，说明必要假设并继续。只有缺少会实质影响正确性、授权范围或不可逆后果且无法合理推断的信息时，才暂停依赖该信息的动作并询问；继续其余已授权工作。
- 如果本技能导致暂停或偏离用户意图，链接实际读取的 SKILL.md、引用具体条款并说明证据，区分明确要求与自己的判断。

## 停止探索并交付

能说明相关位置、适用约束、必要复用、验证方式及剩余实质不确定性，且继续搜索不会改变当前决策时，停止探索。实现任务随即推进实现，调研任务交付结论；停止探索不等于结束整个任务。

验证应覆盖变更行为和项目必要检查。小改动采用相称检查；通过后，只有新修改、失败或具体未决问题才支持扩大或重复验证。测试不可执行时说明未验证的行为与已完成的替代检查，不为了消除所有未知而扩大任务范围。

默认用简短自然语言报告影响方案、范围或风险的发现。计划或审查按用户格式给出结论、关键证据、影响面与未决问题；无需固定的 Fact/Inference/Unknown 栏目、完整清单或独立上下文报告。

本技能依据 [GPT‑6 Astra 提示最佳实践](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices) 调整自主推进、指令边界与相称验证（核对于 2026-09-07）。具体取证策略是本技能的设计选择。
